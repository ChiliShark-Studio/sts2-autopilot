# 独立牌组四维评估

输入牌组，分别计算伤害、防御、费用、启动。不输出总分，不连接游戏或 LLM，不改变自动选路和构筑行为。

在仓库根目录运行：

```sh
python3 -m brain.sim.evaluator --from brain/sim/evaluator/example.json
python3 -m brain.sim.evaluator --from deck.json --candidate candidate.json
python3 -m brain.sim.evaluator --from deck.json --boss vantom
python3 -m brain.sim.evaluator --from deck.json --boss ceremonial_beast
python3 -m unittest discover -s brain/sim/evaluator/tests -t .
```

Python 入口：

```python
from brain.sim.evaluator import evaluate, compare, fight_boss

report = evaluate({
    "deck": ["打击", "防御", {"name": "直接攻击", "cost": 1, "damage": 10}],
    "energy_by_turn": [4, 3, 3, 3, 3],
    "key_cards": ["直接攻击"],
})
comparison = compare({"deck": ["打击", "防御"]}, {"name": "攻击", "cost": 1, "damage": 10})
boss_result = fight_boss({"deck": ["打击", "防御", "武装"], "runs": 100}, "vantom")
```

## 输入

- `deck`：非空数组。可以用已收录的中文牌名，或显式效果对象。`count` 表示张数。
- 显式卡牌支持 `DeckCard` 的字段，例如 `cost`、`damage`、`block`、`hits`、`draw`、`energy`、`strength`、`vulnerable`、`weak`、`exhaust`、`hp_cost`，以及现有模拟器的能力字段。`type` 可明确填写 `attack`、`skill`、`power`、`status`、`curse`。显式对象表示调用方已完整描述该牌的效果，不与同名目录条目混合补值。描述文本不会自动被当成已支持的规则。
  工具另支持 `draw_per_vulnerable`（每次给予易伤时抽牌，层数不乘抽牌量）和 `topdeck`（先抽牌，再将指定张数的手牌放回牌堆顶）。已按本地资料接入凶恶和深谋远虑；深谋远虑的回放描述中附加的“昏眩”属于当回合状态，不是卡牌固有效果。放回牌堆顶复用线上 `SelectAgent` 的战斗选牌分支，不额外使用抽牌堆顺序制定策略；先完成放回，再结算消耗触发。凶恶只在目标仍存活时触发，当前打出的牌在抽牌时尚未进入弃牌堆。
- `turns`：默认 5，最多 50。`runs`：默认 100，最多 1000。`seed`：默认 0。洗牌种子依次为 `seed ... seed+runs-1`。
- `base_energy`：不含遗物的每回合基础能量，默认 3。`draw_by_turn`：外部总抽牌量，默认每回合 5。
- `energy_by_turn`：可选，直接提供**已经包含遗物的外部总能量**，整数表示每回合相同，也可用长度等于 `turns` 的数组。与卡牌实际产能分开；不能再叠加遗物能量。
- `relics`：可选，包含 `name` 和显式 `effects`。支持 `energy_by_turn`、`draw_by_turn` 增量，`starting_strength`、`starting_block`，以及 `carry_energy`。单次或条件效果由调用方依据实际规则展开为逐回合数组。缺少效果或包含其他效果时返回不支持，不根据遗物名字猜数值。
  对日志中的 `BURNING_BLOOD`、`POMANDER`，只有 ID 和已核对的完整描述匹配时，才允许直接输入原始遗物对象：燃烧之血只在战后治疗，胜利剩余血量不包含这次治疗；橙型香盒的拾取升级必须已经体现在牌组中，不重复应用。未知或描述变化的遗物仍返回未覆盖。
- `hp`：默认 80；`enemy_hp`：默认 100000；`incoming_by_turn`：默认每回合 10 点攻击。这些是受控单体木桩参数，不是真实敌人的规则。血量会实际下降，不会为了凑够观察回合而复活。
- `key_cards`：记录这些牌首次抽到、打出、触发效果的时间；默认选能力牌。
- `startup_groups`：例如 `{"格挡转伤害": ["壁垒", "全身撞击"]}`。条件是这些组件已作为能力牌激活或在同一回合打出；不意味着循环已成立。

`character` 默认 `IRONCLAD`。角色名不会自动添加起始遗物或治疗。使用其他角色专属规则时返回未覆盖。

## 武装与 Boss 模拟

武装先获得格挡，再升级剩余手牌中的一张；升级选择、战斗搜索和模拟共用 `brain/upgrades.py`。按已知升级增量选择目标，格挡增量沿用随当前生命变化的权重；同分保持候选顺序。武装+升级所有可升级手牌。升级在本场战斗后续抽取时保留，新种子重新从输入牌组开始。升级数值来自仓库 `data/cards/ironclad.json`，目前只核对打击、防御、痛击、耸肩无视、武装；保留输入中已有的附加数值，只叠加已核对差值。其他未核对目标返回缺失规则，不猜升级增量。`startup.cards_upgraded_by_turn` 记录实际升级张数。

`fight_boss` 复用现有竞技场的整场循环及 Boss 场景，沿用同一工具实例中的资源、升级和状态规则。当前接入墨影幻灵、仪式兽两个单体脚本；不会把木桩攻击时间表覆盖到 Boss 上。昏眩出牌限制和 Boss 塞入的状态牌在后续重读中保留。

Boss 回合上限默认 50，可用 `--max-turns` 或 Python 参数调整。资源时间表必须覆盖完整上限；短数组不会自动外推。固定每回合资源可传整数，首回合/条件遗物需提供完整数组。`observations` 保留每个种子的胜负、回合、剩余血、Boss 剩余血、实际升级张数。原引擎 `damage_taken` 可含致死溢出，实际生命损失应读取 `hp_loss`。

搜索已模拟本回合升级后的手牌，升级带来的即时伤害和格挡直接进入后续出牌结算。跨回合部分单独做有上限的估算：沿用现有敌人生命估计的剩余 1–5 回合，按之后每回合 5 抽，先扣除当前抽牌堆，再除以下次洗牌池规模（当前抽牌堆、弃牌堆、手牌之和，扣除本轮新消耗）。再抽取系数限制在 0–1，只计算未来一次已知升级增量；当前回合已经兑现的收益不重复相加。牌堆信息不足、已经斩杀、预计本回合结束战斗时不给这项收益，消耗牌和能力牌不计重复使用。

这只是有限的收益估计，不是精确的再抽取概率或胜率。决策日志 `extra.upgrade_future` 保存系数、已知增量与估值。搜索排序先比较斩杀、能否保命，最后比较评分，不能用未来收益压过已经找到的保命方案。抽牌后的具体手牌和完整多回合成长仍未搜索，不能把未充分利用的配合直接判为卡牌无效。

## 卡牌类与共享结算

卡牌定义统一登记在 `brain/cards/`：`BaseCard` 定义接口，每种牌各有独立子类，`CardType` 区分攻击、技能与能力。同一牌的已知升级版由同一子类的 `upgraded` 参数表示；注册表按 `known_versions` 提供已经录入的版本，不为缺少升级数据的牌推测数值。原模拟目录的 38 种牌已迁入，连同 `Rage`、`DemonForm` 共 40 种、52 个已知版本。`brain/sim/deck.py` 从子类装配独立战斗实例，不另存数值表。

当前只有狂怒和恶魔形态通过 `effects` 提供完整共享效果，并通过 `play(state)` 调用共享结算。其他旧模板通过 `simulation_fields()` 提供原有数值，仍沿用现有引擎结算；迁移目录不代表这些牌的规则已经完整覆盖。

两张牌在各自的 `effects` 中声明完整 `TriggeredEffect`，包含状态 ID、触发事件、执行动作、数值和失效事件。不再维护 `POWERS` 规则表。战斗侧共享模块 `brain/combat/effects.py` 负责效果执行、生效状态管理和事件分发；卡牌侧 `brain/cards/effects.py` 保留效果声明、能力查询及旧模型适配。打出后，战斗状态保存独立的 `ActiveEffect`，其中持有该规则并累计层数；卡牌离开手牌后效果仍可持续。战斗流程调用 `emit()`，按生效实例中的规则触发和清除状态；`capability()` 直接查询卡牌提供的规则。读取真实游戏状态时，从注册卡牌的效果声明派生恢复索引，不另存触发或持续时间规则。相同状态 ID 的不同数值可以叠加，行为规则冲突时直接报错。

```python
from brain.cards import CardType, EffectKind, Event, get_card

rage = get_card("RAGE", upgraded=True)  # Rage 子类，升级后每次触发获得 5 格挡
assert rage.type is CardType.SKILL
assert rage.amount(Event.ATTACK_RESOLVED, EffectKind.GAIN_BLOCK) == 5
```

注册表只负责 ID 到具体子类的映射；名字查询仅保留在输入边界。原 `DeckCard` 保存本场卡牌实例数据，并通过 `definition` 持有不可变的卡牌子类实例。模拟器加载后实际调用其 `play()`；战斗搜索读取相同的结构化效果并调用同一份结算。狂怒的攻击后触发、回合结束移除，以及恶魔形态的回合初成长都由共享 `emit()` 处理，评估器只观察触发结果。标准的这两张牌不再通过生成中文描述供搜索重新解析。显式自定义数值、真实桥接文本仍在输入适配边界处理。

旧 `brain/sim/ironclad.py` 及其数值字典已移除；评估器从卡牌子类派生数值目录。评估器本地已核对的额外规则仍保留，例如预备打击的临时力量不会退回旧模板的永久力量。旋风斩已补齐动态 X 费、按 X 重复命中和群体目标；其他尚未完整支持的牌仍拒绝完整评估。完整规则共享执行、不同版本数据的统一核对需另行迁移。

## X 费

X 费保留为费用类型，实际出牌时读取该分支的剩余能量。先出固定费牌会减少 X，先产能会增加 X；零能量对应零次命中。旋风斩每次对所有存活敌人造成基础版 5、升级版 8 点伤害，伤害修正逐次结算。搜索中的复制使用同一次出牌确定的 X，不再次扣费。

显式输入可写 `{"name": "X 攻击", "cost": "X", "damage": 5, "hits_x": true}`；也可用整数占位费用加 `cost_x: true` 表示 X 费。`hits_x` 表示按出牌前能量重复攻击。其他未声明如何按 X 结算的效果返回未支持，不推测格挡或其他资源收益。

费用维度的 `energy_spent` 记录实际消耗；`printed_average` 只计算固定费牌，没有固定费牌时为 `null`。含 X 费牌时单列 `x_cost_cards`，不会把整数占位值 0 当成零费牌计入平均费用。当前评估器仍只运行单体遭遇，群体结算的一致性由独立回归测试覆盖。

## 四维口径

| 维度 | 输出和单位 |
|---|---|
| 伤害 `damage` | 逐回合实际扣除的敌人生命，前两回合累计伤害，观察期平均伤害；伤害不超过剩余敌人生命 |
| 防御 `defense` | 新生成格挡、实际挡住的敌人攻击、虚弱减少的攻击、敌人造成的掉血、自伤及状态牌掉血；状态牌消耗的格挡单列 |
| 费用 `cost` | 牌面平均费用，以及逐回合起始、生成、消耗、剩余能量；原有能量保留后计入下回合起始能量 |
| 启动 `startup` | 全部初始牌首次被看见所需回合、实际抽牌量、关键牌与指定组件的观测时间 |

各数值提供样本数、均值、中位数、最近秩 P10/P90。启动时间另列 `not_observed`，不能把未启动记成 0 回合。`unaffordable_cards` 只表示回合末费用高于剩余能量的手牌数量，不直接证明“缺能量”或“该删牌”。

## 社区 25 张力量构筑

`community_strength25.json` 原样保存 [the_shadow_fox 分享的 25 张完整牌表](https://www.sts2companion.com/decks/2362cab1-f1ef-4176-85aa-9d600cf018f8)，全部未升级。分享页没有可核实的通关记录，其“73%”是网站的构筑匹配标记，不能当作实战胜率。未提供遗物、药水或入场血量，本工具的基准明确采用 80 血、基础 3 能量、每回合 5 抽、无战斗遗物和药水。薪火之源、跃跃欲试的产能由实际结算另计。

```sh
python3 -m brain.sim.evaluator --from brain/sim/evaluator/community_strength25.json
python3 -m brain.sim.evaluator --from brain/sim/evaluator/community_strength25.json --boss ceremonial_beast
```

规则数值来自 2026-11-13 读取的 [Spire Codex 稳定版卡牌接口](https://spire-codex.com/api/cards?lang=zhs)，对应字段、原始卡牌 ID 和升级索引保存在 `tests/strength25_source.json`，离线测试不访问网络。该接口当次没有提供可核实的游戏版本号，因此本次是按保存的效果快照回测，不声称适配当前客户端或 beta。尤其跃跃欲试采用快照中的“按手牌攻击数产能后禁止继续产能”，不混入其他版本的重做。

| 规则 | 结算口径 |
|---|---|
| 完美打击 | 6 加每张 Strike 标签牌 2 点；本牌及消耗堆中的牌也计入。本套牌共 12 张，基础伤害 30 |
| 预备打击 | 先造成 7 点伤害，再增加本回合的 2 点力量；回合结束移除临时部分 |
| 跃跃欲试 | 扣除 2 费后，按当时手牌中的攻击牌数获得能量；本回合后续产能被阻止 |
| 非凡技艺 | 永久获得 1 力量和 1 敏捷；能力牌离开循环牌堆 |
| 薪火之源 / 恶魔形态 | 从下回合开始分别增加 1 能量 / 2 力量；产能发生在抽牌及其自动出牌之前 |
| 地狱狂徒 | 逐张抽牌时自动免费打出 Strike 标签牌。抽牌仍消耗本次抽牌次数；剑柄打击自己的抽牌另算。昏眩会阻止后续自动出牌并将相应牌置入弃牌堆 |
| 狂怒 | 本回合每打出一张攻击牌，在该牌结算后获得 3 格挡；不按命中次数触发，不加敏捷，回合结束清除 |
| 神气制胜 | 不计自身；之后每完成五张牌造成 10 点无属性伤害，不受力量、易伤增幅；自动出牌也计数，回合末重置计数 |
| 焚烧 | 每次命中分别增加力量；当前工具仅接受单体遭遇，在单体中完整结算四次命中，不对多目标结果作推断 |

事件顺序另对照游戏的公开反编译源码：[自动出牌](https://github.com/zhiyue/sts2-rl-agent/blob/main/decompiled/MegaCrit.Sts2.Core.Commands/CardCmd.cs)、[地狱狂徒](https://github.com/zhiyue/sts2-rl-agent/blob/main/decompiled/MegaCrit.Sts2.Core.Models.Powers/HellraiserPower.cs)、[神气制胜](https://github.com/zhiyue/sts2-rl-agent/blob/main/decompiled/MegaCrit.Sts2.Core.Models.Powers/PanachePower.cs)、[昏眩](https://github.com/zhiyue/sts2-rl-agent/blob/main/decompiled/MegaCrit.Sts2.Core.Models.Powers/RingingPower.cs)。只独立实现本工具所需规则，不引入该项目的模拟器或决策策略。

`startup.automatic_cards_by_turn`、`automatic_blocked_by_turn` 记录自动出牌和被阻止的数量。Boss 的每个种子另列核心牌首次打出、首次触发时间、自动出牌总数及实际产能，并包含胜利所在的最后一回合。嵌套抽牌引发的伤害和格挡只统计一次。

评估器与线上共用 `decide_state`，不强制打成长牌。第一轮搜索已补齐狂怒的攻击后格挡、预备打击的临时力量、跃跃欲试按剩余手牌重新计数及禁止继续产能；没有格挡效果的牌不再因为敏捷凭空产生格挡。每次重读状态都恢复当前狂怒、临时力量及产能限制，不能只在同一次搜索中保留。

恶魔形态的未来收益以新增的每回合力量乘预计命中数估算。预计攻击张数取“每回合基础 5 抽乘牌组攻击比例”和“未来能量预算除平均攻击费用（分母至少为 1）”中的较小值，再乘平均命中次数。能量预算为基础上限加已生效或本方案新增的薪火之源，不把跃跃欲试等条件产能当作每回合固定能量。观察期限用剩余敌人生命与预计基础伤害估算，最多 4 个未来回合；每轮累积力量，按预测伤害推进剩余生命，额外收益不超过该轮剩余生命。缺少牌组攻击信息或已经斩杀时，成长估值为零。临时力量不进入永久成长奖励或未来基础伤害。

日志 `extra.strength_future` 保留新增每回合力量、估计回合数、每回合命中数、能量预算及收益。此估计使用公开牌表，不读取实际抽牌顺序；没有完整预估未来防御、抽牌连锁、遗物条件和 Boss 后续意图，不是完整多回合搜索。地狱狂徒和神气制胜的搜索收益留待后续验证，结算仍会忠实执行。需要同时查看打出和触发情况，不能把算法漏用核心牌解释为该构筑没有强度。

格挡只在实际被消耗时计入有效防御，壁垒保留的同一份格挡不会跨回合重复计数。伤害、防御、费用和启动来自同一场执行过程，不拼接不同最优方案。

提前获胜、死亡、达到观察上限、动作不支持分别计数。没有观测的后续回合不补零；前两回合和观察期均值只包含对应窗口齐全的样本。不同回合、不同构筑的有效样本数可能不同，需要连同终止结果一起看。P10/P90 是采样分位数，不是最坏情况保证。

## 覆盖与策略局限

复用 `brain.sim.engine.Fight` 和线上同一个 `brain.combat.search.decide_state`。本工具只在自己的观测实例中记录过程、正确区分能力牌与技能、按资源时间表运行并执行已核对的武装升级；不会修补线上战斗行为。能力牌进入能力区，不会重新洗回牌堆。

共享引擎和策略不是完整游戏实现。搜索对抽牌后续、能力和消耗触发的估值有限，可能不打出某些实际有潜力的启动牌。报告表示**当前策略在指定基准下的执行表现**，不声称接近最优，也不代表精英安全或通关概率。多目标、随机目标、其他选牌、未知附魔等尚未覆盖的效果不能降级成基础伤害；必须返回缺失清单。按牌名读取的现有目录仍需与本机游戏版本核对。

`status=unsupported` 时四维为 `null`，`coverage.missing` 列出原因。运行中出现不支持动作时为 `incomplete`，不把失败的半个回合混入完整回合统计。CLI 成功返回 0，输入错误返回 2，不支持或未完成返回 3。

候选比较返回两份完整报告和 `mean_delta`。差值保留四个维度，不生成统一排名，也不把均值差称为统计显著。两份构筑使用相同预算、策略和种子，但牌数变化会改变洗牌映射，同种子不是完全相同牌序。

## 提供给模型的内容

报告的 `context` 保留角色、遗物、逐回合资源和基准条件；`model_guidance` 要求模型分别描述四维的当前值、目标依据、缺口与取舍。模型应结合已知遭遇制定目标，不能把首回合加费当作永久加费，或把已计入总量的遗物重复相加。缺少真实遭遇或规则覆盖时，目标数字标为待验证。

来源：[Baalorlord 的构筑基础](https://sts2.untapped.gg/en/articles/core-deckbuilding-concepts-in-slay-the-spire)提供回合伤害、成长、循环时间、防御密度的分析思路；[StS2Sim](https://next.tangled.org/cee.wtf/sts2-sim)提供按洗牌种子观测伤害的参考。本工具的四维字段、默认预算和统计口径是本项目的实现选择，不是这些来源验证过的通关标准。
