# 方案实施 TODO

目标：让零 LLM 的战斗算法负责执行，让选路与按角色定制的构筑 LLM 调用可信模拟器辅助决策，最终推进铁甲战士 A0 至 A10。方案与职责见 [架构](architecture.md)。

以下均为待办，未声明已经实现或验证。按顺序逐项推进，每项开始前确认最小范围；测试代码须单独确认，运行验证命令须列入该项方案。当前只更新文档。

## 第一阶段：打通一个可信的模拟案例

- [ ] **T01：确定模拟输入、输出与首批覆盖范围。** 明确真实构筑快照、候选变化、遭遇 ID、种子和预算的输入形状，以及胜负、未完成、规则缺失的输出语义。选择一个真实精英遭遇和一套铁甲战士构筑，逐项列出必须支持的卡牌、遗物、药水与敌人机制。验收：形成可评审的请求 / 响应示例、规则覆盖清单和来源，不把样例怪物当作真实数据。
- [ ] **T02：补齐首批玩家规则。** 扩展现有 `brain/sim/`，按 ID 解析首批卡牌、升级、遗物、药水和角色初始效果，明确触发顺序、抽牌、弃牌与消耗的结算。不休陀螺等效果须先核实当前版本规则再实现。验收：选定构筑完整受支持，未知关键效果明确拒绝评估；与战斗搜索重复的结算规则逐项核对。
- [ ] **T03：建立首个真实精英遭遇。** 核实怪物生命范围、初始状态、行动规则、随机分支、难度差异及阶段切换，复用现有场景和特殊意图机制。验收：说明规则来源及适用版本，能复现选定的真实行动片段；缺失后续行动不能悄悄循环替代。
- [ ] **T04：验证首个完整模拟案例。** 用实际战斗策略跑完整场，并对照真实游戏记录检查关键结算；核对非法动作、不支持药水动作、脚本耗尽和运行上限的处理。验收：得到可复现的完整案例，记录已核实范围、策略局限和剩余偏差，再进入决策接入。

## 第二阶段：把模拟器变成 LLM 可调用的工具

- [ ] **T05：补齐批量评估与结构化调用。** 提供选路和构筑共用的模拟入口，支持多遭遇、多种子及候选构筑比较。返回胜 / 负 / 未完成、胜率分母、损血和剩余血量分布、回合与药水消耗、覆盖说明；区分获胜样本与失败 / 未完成样本的统计。验收：相同输入和种子可复现，候选比较使用相同种子和遭遇，工具请求有明确预算，单场战斗不调用 LLM。

## 第三阶段：角色构筑与选路接入

- [ ] **T06：整理铁甲战士构筑与路线攻略。** 标明版本与依据，描述构筑方向、核心组件、过渡选择、关键遗物 / 药水、删牌 / 升级原则及候选精英机制。采用同一 LLM 配角色资料，不先训练独立模型。验收：区分已核实知识与待确认项，早期允许多方向过渡，资料覆盖首批模拟案例。
- [ ] **T07：统一构筑 LLM 决策。** 在现有 `BuildAgent / BuildFlowTool` 与选牌入口内接通奖励选牌、选药 / 换药、事件、商店购卡 / 遗物 / 药水 / 删牌、遗物选择、篝火与永久升级。输入完整卡组效果、遗物、药水和合法候选，维护当前组件、短板与下一步需求；需要比较时调用模拟器，每次操作后重读状态。验收：上述决策围绕同一构筑判断，资源和候选由程序校验；购买删牌服务到选牌确认可完成；战斗内临时选牌不交给构筑 LLM。
- [ ] **T08：接入基于模拟结果的选路。** 路线 LLM 读取构筑需求、攻略和最新资源，调用模拟器评估已知候选精英池，再比较恢复、成长与后续路线。验收：理由引用实际工具结果，未完成或未覆盖的模拟不能视作安全；未知敌人不被当作已知，未模拟的未来节点不被描述成已验证。

## 第四阶段：逐局校准与扩大覆盖

- [ ] **T09：建立预测与实战复盘。** 关联模拟请求、规则 / 策略版本、种子、LLM 判断及实际战斗结果，排查规则误差、信息不足和策略不足。验收：可以追踪一次选路 / 构筑决定的依据与实际代价，不把离线局部通过写成真机验证。
- [ ] **T10：按对局需要扩展覆盖。** 铁甲战士先覆盖实际遇到的卡牌、遗物、药水和各阶段遭遇，再接入其他角色资料与规则；根据复盘改进战斗算法对抽牌及配合的利用。保留 A0 稳定胜率、自动重开、逐级爬升至 A10 的长期目标。验收：每次明确新增规则与验证范围，不以凑齐百科为目标，不提前扩展到全角色全规则。

## 暂不展开

本轮不新建独立模拟器项目、不引入通用插件框架、不训练角色专用模型、不迁移到 C#。先复用现有分层与 `brain/sim/`，需要扩展范围时另行确认。
